You are annotating a findings report with the Slack handles of the developers who last touched the root cause code.

INPUT FILES:
- `/tmp/analysis_findings.md` — the findings report (read AND write)
- `/tmp/slack_email_map.json` — pre-built mapping with two sections:
  - `by_email`: `{ "email@example.com": { "slack_id": "U...", "display_name": "...", "real_name": "..." } }`
  - `by_name`: `{ "lowercase git name": "email@example.com" }` (fallback)

PROCEDURE:

1. Read `/tmp/analysis_findings.md`. Identify every insight/finding that references source files or function names.

2. For each insight, determine the relevant source files in this repository. Look for:
   - File paths explicitly mentioned (e.g., `src/foo/bar.ts`)
  - Function names — search the repo with `git grep -n "function_name"` (prefer narrowing to likely paths like `apps/` or `libs/`)
   - If the insight references a service/module name, look in the likely directory (e.g., `apps/`, `libs/`)

3. For each relevant file, run `git blame` to find the last 3 unique authors of the key lines:
   ```
   git blame --line-porcelain <file> | grep "^author-mail" | sort | uniq -c | sort -rn | head -5
   ```
   This gives you the top authors by line count. Extract their email addresses.

4. Read `/tmp/slack_email_map.json`. For each author email:
   - Look up in `by_email` → get `slack_id`
   - If not found (e.g., GitHub noreply emails), extract the author name from git blame output and look up in `by_name` → get the email → then look up in `by_email`
   - Format as `<@SLACK_USER_ID>` (e.g., `<@U04ABCDEF>`) — this is how Slack renders @mentions

5. For each insight in the findings, append a line after the root cause or function details:
   ```
   **Contributors:** <@U04ABCDEF>, <@U05GHIJKL>, <@U06MNOPQR>
   ```
   Include up to 3 unique Slack users per insight. If no Slack mapping exists for an author, skip them (don't include raw emails).

6. Write the updated content back to `/tmp/analysis_findings.md`.

RULES:
- Do NOT delete or rewrite any existing content — only INSERT the **Contributors** lines.
- Do NOT include raw emails or git usernames in the output — only `<@SLACK_ID>` tags.
- If you cannot find the file in the repo (e.g., it's in an external dependency), skip that insight.
- If `/tmp/slack_email_map.json` is missing or empty, skip the Slack lookup and just add git author names as a fallback: `**Contributors:** Author Name, Author Name2`
- Be efficient: don't blame files that aren't in this repository.
